## About

JXRouter (JXProxy) — a macOS menu-bar proxy app that routes AI API traffic (Claude Code, Codex, OpenAI SDK clients) through configured LLM providers. Native SwiftUI/AppKit, no web admin, no /etc/hosts edits.

- 2026-09-20: Fixed two user-reported bugs — "only Ornith is detected" and "it keeps deleting my API keys":
  1. **Model list truncated to one entry.** `GGUFParser.metadata()` issued one `read()` syscall per scalar value, so a single GGUF header cost ~1.5s. `scan()`'s 5s budget was consumed by the first file, so the list showed only the first (largest) model. Rewrote it as a buffered parser with a `Cursor` walking an in-memory slice using `loadUnaligned`: **1.5s → 0.006s per file**. `skipArrayElements` now skips by byte stride instead of materialising elements — vocabularies are ~250k strings (`tokenizer.ggml.tokens`).
  2. **Partial header parses silently dropped the chat template.** When a header didn't fit the buffer the parser returned the metadata it had; because the huge tokens array precedes `tokenizer.chat_template`, every model came back template-less and flipped to `nativeToolCalling=false`. The parser now returns `nil` (grow the buffer and retry) when it runs out, and the buffer grows geometrically.
  3. **Discovery no longer scans the disk per model.** `readGGUFMetadata` called `findMatchingMmproj`, which widened to a full `scanMmprojFiles` disk scan for every file (`~/Downloads` alone takes ~7s to enumerate). Discovery now matches projectors from the model's own folder only (`widen: false`); widening still happens on selection, where one scan is affordable. Also skips listing the home directory as a "parent" candidate. Result: all 4 models in `~/Models` are detected with correct arch/ctx/projector, all `nativeToolCalling=true`.
  4. **API keys were being deleted.** `saveConfig()` wrote every provider key when `lastSavedValues[field] != value || getApiKey(...) != value`. If a Keychain read ever came back empty (transient timeout, reload racing a stalled keychain, shell-config watcher), the field was `""`, which compared unequal to the real stored key and triggered `setApiKey("")`. Same pattern in the `customKey` and custom-provider loops; `upsertCustomProvider` deleted on every save where its field was empty. An empty field now clears a key **only** when it previously held a value — i.e. the user actually emptied it. Removed the unconditional custom-key write and added `guard !apiKey.isEmpty` to `upsertCustomProvider`. Remove-button and `removeCustomProvider` clearing still work.
  5. Note: there is **no** configurable "local model folder" and none was removed — `defaultSearchPaths` is hardcoded (`~/Models`, `~/.local/share/llama.cpp/models`, `~/Downloads`, `/Volumes/*/Models`) and is unchanged.
